# Proton2025 Theme Installer for OpenWrt

Установка и обновление оригинального `ChesterGoodiny/luci-theme-proton2025`.
Собственного форка темы здесь нет. Если тема уже установлена, та же команда
запускает обновление с резервной копией, проверкой LuCI и автономным откатом.
RouterDesk использует копию того же проверенного механизма из `lib/`.

## Установка или обновление

Скачайте и просмотрите скрипт, затем запустите от root на OpenWrt:

```sh
curl -fsSL https://raw.githubusercontent.com/moz9/proton2025-theme-installer/main/install-proton2025-theme.sh -o /tmp/install-proton2025-theme.sh
PROTON2025_VERSION=v1.4.4 sh /tmp/install-proton2025-theme.sh
```

Одна команда для обеих ситуаций:

```sh
curl -fsSL https://raw.githubusercontent.com/moz9/proton2025-theme-installer/main/install-proton2025-theme.sh -o /tmp/install-proton2025-theme.sh && PROTON2025_VERSION=v1.4.4 sh /tmp/install-proton2025-theme.sh
```

Повторный запуск для уже установленной версии ничего не меняет. Понижение
версии этой командой запрещено. Скрипт загружает вспомогательные файлы с
закреплёнными SHA-256: смешивание разных ревизий прекращает запуск.

Версию задавайте явно: скрипт не использует плавающий `latest`.
Требуются `jsonfilter` (обычно есть на OpenWrt) или `jq`, `sha256sum`,
`uci`, HTTPS downloader и `apk`/`opkg`.
Пакет выбирается по точному имени, тегу и upstream GitHub URL;
дубликаты отклоняются. Перед установкой обязателен SHA-256 digest
из GitHub Release API. Это проверка целостности по metadata GitHub,
не независимая подпись автора. Для APK ожидается revision `r1`;
иной формат имени намеренно требует пересмотра установщика.
Несохранённые изменения UCI блокируют запуск. Файлы темы/RPC без установленного
пакета блокируют первую установку: чужие или остаточные файлы не перезаписываются.

По умолчанию выбранная тема сохраняется: конфигурация LuCI копируется
перед пакетной операцией и восстанавливается после неё, в том числе
при обнаруженной ошибке. Чтобы явно включить Proton2025 при первой установке:

```sh
PROTON2025_VERSION=v1.4.4 PROTON2025_ACTIVATE=1 sh /tmp/install-proton2025-theme.sh
```

## Обновление и зависимости

До изменения темы скачиваются точные старый и новый пакеты. В приватной папке
`/root/routerdesk/<id>` сохраняются исходные файлы, настройки и журнал.
RouterDesk дополнительно сохраняет проверенные зашифрованные копии на ПК;
самостоятельная команда не обещает копию на ПК. После отправки установки
независимый watchdog откатывает её через 180 секунд без подтверждения.
Подтверждение требует проверки версии, настроек, страницы LuCI и CSS; для
новых тем проверяется также JSON-RPC `/ubus`. Успех пакетного менеджера сам
по себе не считается успехом обновления.

Автоматически добавляется только отсутствующий `uhttpd-mod-ubus`:

- IPK берётся из подписанного официального индекса **той же** версии OpenWrt
  и архитектуры, проверяется SHA-256, имя, зависимости и разрешённые файлы.
- Версия модуля должна точно совпадать с установленным `uhttpd`; системные
  библиотеки и веб-сервер не обновляются ради темы.
- APK загружается штатным менеджером с проверкой доверия и ограничением
  плана только на добавление этого модуля. Сторонние изменения отклоняются.
- Если `/ubus` отсутствует, добавляется только этот параметр. Нестандартный
  адрес не перезаписывается. Исходная конфигурация включена в откат.
- При сбое откатывается тема, восстанавливается конфигурация веб-сервера,
  удаляется добавленный этой операцией модуль. Ранее установленный модуль
  не удаляется. Неудача отката остаётся явной ошибкой, а не «успехом».

Если точный пакет недоступен или для него не хватает библиотек, установка
не начинается. Это граница автоматического обновления, не повод использовать
`--force-depends` или менять репозитории прошивки.

## Границы первой установки и восстановления

Bootstrap не является атомарной транзакцией и не откатывает пакет или
все файлы при частичной ошибке пакетного менеджера, отключении питания
или SIGKILL. Восстановление LuCI config — ограниченная страховка, не
доказательство работоспособности LuCI. Ошибки restart не скрываются.
Перед установкой нужен резервный backup и независимый SSH-доступ.
Эти ограничения bootstrap относятся к **первой установке**. Обновление уже
установленной темы использует описанную выше транзакцию. Автооткат защищает
от ошибок установки и потери SSH, но не от выключения питания/перезагрузки
роутера: сохранённая копия остаётся для ручного восстановления.

Установщик больше не создаёт `proton2025-download` и не патчит upstream
RPC updater через awk. На уже установленных роутерах прежний helper
и patch автоматически не удаляются. Встроенный updater самой темы
не становится транзакционным и этим проектом не проверен: обновляйте тем же
скриптом или через RouterDesk, а не встроенной кнопкой upstream.

## Удаление

`uninstall-proton2025-theme.sh` — legacy removal: он переключает тему
на bootstrap и удаляет пакет. Автоматического отката удаления нет.
Не запускайте его как восстановление после неудачного обновления.

## Локальная проверка

```sh
python -m unittest discover -s tests -v
sh tests/upgrade.sh
```

Тесты используют Git Bash на Windows или Bash на Linux (путь можно задать
переменной `BASH`). Проверяются helpers и полный bootstrap с изолированной
файловой системой и имитацией пакетного менеджера: первый запуск, явная
активация, ошибки SHA-256/установки/restart,
сохранение конфигурации и отказ при несохранённых изменениях UCI.
Asset selection использует адаптер JSON в тесте; native jsonfilter/jq
и работа LuCI требуют отдельной проверки на OpenWrt.
`tests/upgrade.sh` проверяет реальный механизм обновления и откат при ошибке
LuCI в изолированной файловой системе Linux/WSL. Пакетный менеджер и сеть
подменены; это не результат на живом роутере.
